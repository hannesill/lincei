# T3 Code → Lincei alpha port ledger

## Audit boundary

- Upstream: `pingdotgg/t3code`
- Audited cutoff: `887dd6e455bb969c1a0c9659a6bdf2baceac030d`
  (`perf(server): negotiate permessage-deflate on the websocket (#4705)`)
- Local `t3code/main` at audit: the same SHA; delta after the cutoff: `0` commits.
- All SHAs below are ancestors of the cutoff and their titles/PR references were verified
  from the local `t3code` objects.
- `—` in the PR column means the commit title does not encode a PR number.

The status vocabulary is intentionally closed:

- `ported`: the upstream behavior is selected for the alpha and implemented with a
  Lincei-specific adaptation.
- `equivalent`: audited Lincei behavior already provides the relevant outcome.
- `deferred`: relevant behavior is intentionally postponed with its risk recorded.
- `not applicable`: the change targets excluded or absent upstream architecture, or was
  superseded before the cutoff.

Local commit SHAs are exact where the cohort is already on the integration branch.
`PENDING-SIDEBAR-SERVER`, `PENDING-SIDEBAR-UI`, and `PENDING-COSMETIC` are qualification
placeholders, not integration evidence. Replace every pending marker with the final rebased
commit SHA(s) before approval. A `ported` row with a pending marker records the audited final
disposition, not a claim that the cohort is already integrated.
